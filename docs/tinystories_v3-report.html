Abstract

The TinyStories line of work shows that small language models trained on narrow, high-quality synthetic text can produce coherent narratives. We take a pretrained SmolLM2-135M and fine-tune it with LoRA on the TF1-EN-3M corpus of synthetic moral fables, treating one question as the object of study: where the low-rank adapters should be placed. Holding rank, data, and schedule fixed, we compare a floor (no fine-tuning) against three placements — attention q,v across all layers (A), the same restricted to the last third (B), and all seven linear projections across all layers (C). Validation perplexity falls from 9.52 (base) to 3.84 (C), and readability moves from effectively unreadable to age-appropriate. The two contrasts answer the title: adapting all layers beats the last third, but the larger win by far comes from breadth — adding the MLP projections. The project is a deliberate counterpoint to a sibling project that fine-tunes a 4-billion-parameter model, and is delivered end-to-end: trained, evaluated, exported to GGUF, and served through Ollama inside that sibling's application.

01Introduction

Fables are a compact, highly structured narrative form: a character with a trait, a setting, a challenge, a resolution, and an explicit moral. That regularity makes them an unusually good testbed for small language models — the vocabulary is limited, the arc is short, and quality is legible to any reader. TinyStories [2] showed that models below 10M parameters can write coherent children's stories when the data is curated and narrow, and the dataset we use [1] was built explicitly to be "conducive to parameter-efficient fine-tuning of small downstream models."

Rather than train from scratch, we start from a pretrained small model and adapt it with LoRA [3], which freezes the base and learns small low-rank updates in selected projections. LoRA's placement is usually chosen by convention. The brief made that convention the contribution — "note why we select which layers to add to our model" — which we read precisely as adapter placement.

Research Q

Under a fixed budget (same base, rank, data, and schedule), does adapter placement change fable quality — and which axis matters more, the layers the adapters span or the modules they attach to?

Contributions. (1) A controlled single-variable ablation of LoRA placement for narrative generation on a 135M model, isolating the layer-depth axis (A vs. B) and the module-breadth axis (A vs. C); (2) a quantitative result — module breadth dominates layer depth for this task; (3) a complete, reproducible pipeline with a GGUF→Ollama export into a sibling application.

02Background & theory

2.1  Low-Rank Adaptation (LoRA)

A dense layer computes h = W·x. Full fine-tuning updates all d_out · d_in entries of W. LoRA freezes W and learns a low-rank update:

W' = W + ΔW ,   ΔW = (α / r) · B · A ,   A ∈ ℝ^(r × d_in) ,  B ∈ ℝ^(d_out × r)

with rank r ≪ min(d_in, d_out), B initialised to zero (so training starts exactly at the pretrained model), and fixed scaling α/r. Only A and B train, giving r·(d_in + d_out) parameters per adapted matrix — far fewer than d_in·d_out. At inference BA can be merged back into W, so an adapted model has zero extra latency once merged — which is exactly how we export a single dense model to GGUF (§08).

2.2  Why placement is a real question

LoRA leaves two choices unspecified, and they are the two axes of this study:

  • Which modules? A block has attention projections (q,k,v,o) and MLP projections (gate,up,down). The LoRA paper reports that adapting only W_q, W_v is often sufficient — a claim to test per task, not a law.
  • Which layers? Adapters can cover every layer or a subset; later layers are often argued to carry more task-specific representation, motivating a "last-third-only" efficiency lever.

These axes are usually entangled. Our design (§05.3) deliberately separates them so each can be read on its own.

2.3  Why the fable form suits a small model

The target is deliberately narrow: ~200-word children's fables with a fixed five-element structure and limited vocabulary. A 135M model has neither the capacity nor the need to model open-domain text; the task's narrowness is what makes a tiny model viable and the placement question crisp — there is a real signal to capture, and small differences in where capacity is added become visible in the metrics.

We train on TF1-EN-3M (klusai/ds-tf1-en-3m) [1], three million synthetic English moral fables generated by an 8-billion-parameter instruction model. Each row pairs a structured prompt with a fable and a fixed system message. The prompt renders five labelled slots:

04Positioning vs. tinystory-vn

This project is a deliberate counterpoint to a sibling course project, tinystory-vn, which targets the same dataset and output style from the opposite end of the design space. That project full-fine-tunes a 4-billion-parameter model (Qwen3-4B, SFT + ORPO) and centres its contribution on the application and evaluation methodology — a served app with a multi-layer guardrail and an LLM-judge panel. We deliberately go small and make the model-internal placement question the object of study — an axis that project never explores. §07.6 lays the angles side by side.

05Method

5.1  Base model — and why SmolLM2-135M

We start from SmolLM2-135M (base, non-instruct) [4]: a Llama-style decoder with 30 layers, hidden size 576, 9 attention heads (3 KV heads, grouped-query), MLP intermediate 1536, and a 49,152-token vocabulary. The choice is load-bearing: SmolLM2 keeps separate q/k/v/o and gate/up/down projections, so the textbook "adapt q,v only" contrast is well-defined. A model with a fused QKV projection (e.g. GPT-2's c_attn) cannot separate q from v, which would make the module-axis contrast impossible. Starting from a base (not instruct) checkpoint also gives an honest before/after — the base cannot follow the fable prompt at all. (ADR-0001.)

5.2  Task formulation

Learning is conditional generation: input = system ⧺ prompt, target = fable, with the loss on the fable tokens only — context tokens are masked to the ignore index −100 (completion-only masking) and an end-of-text token is appended so the model learns to stop.

input  =  BOS  s_1 … s_m  (system+prompt)   f_1 … f_n  <eot>
labels = −100 −100 … −100  (masked context)  f_1 … f_n  <eot>
loss   =  −(1/N) · Σ_{t: label_t ≠ −100}  log p(label_t | x_<t)

This keeps the model controllable and, critically for a placement study, makes perplexity a fair, like-for-like signal — every arm is scored under identical masking on identical text.

5.3  The ablation — which layers, which modules

Rank is fixed at r=16 (α=32, dropout 0.05) across all arms so that placement is the only variable. Four configurations:

base
No fine-tuning — pretrained SmolLM2-135M as the reference floor.0 adapted parameters
A
q,v · all 30 layers — the classic minimal LoRA placement.≈ 0.9M params · ≈ 0.68% of the model

A vs. B varies only layer depth; A vs. C varies only module breadth. We verify programmatically that arm B's adapters are confined to layers 20–29 and A's cover all 30, so the claim is not merely nominal. (ADR-0002.)

5.4  Adapted-parameter accounting

LoRA at rank r adds r·(d_in + d_out) parameters per matrix. With SmolLM2's dims:

Against a ≈134.5M base: A (q,v × 30) ≈ 0.92M (0.68%); B (q,v × 10) ≈ 0.31M (0.23%); C (all-7 × 30) ≈ 4.88M (3.5%).

5.5  Training configuration

Each arm trains on a fixed 50,000-fable subset (seed 42, identical across arms) for 2 epochs at sequence length 512: AdamW, lr 2e-4, cosine schedule with 3% warmup, bf16, effective batch 32 (≈ 3,125 steps/arm). Trained on a single Colab L4; adapters push to the Hub, metrics stream to Weights & Biases with a heartbeat callback.

5.6  Evaluation methodology

  • Validation perplexity (primary) — teacher-forced, loss on fable tokens only, token-weighted; identical masking for base and every arm. The natural, API-free, directly-comparable signal for placement.
  • Reference-free metrics on 100 sampled generations/arm (temp 0.8, top-p 0.9, rep-pen 1.3, seeded): Distinct-1/2 (lexical diversity), Self-BLEU (intra-set redundancy; lower = more diverse), Flesch Reading Ease (higher = easier; below 0 = unreadable).
  • LLM-as-judge (planned) — a single local judge over the paper's four axes; deferred as a stretch goal. (ADR-0003.)

07Analysis & discussion

7.1  Fine-tuning works — dramatically

The untrained base cannot follow the prompt: PPL 9.52 and a strongly negative Flesch. Its high Distinct-1 (0.557) and near-zero Self-BLEU (0.007) are not a quality signal — they are the fingerprint of random, unconstrained text, which trivially avoids repetition. Every LoRA arm collapses that randomness into coherent, templated fables. A caution follows: reference-free diversity metrics, read in isolation, can reward incoherence.

Layers

A vs. B — adapting all layers beats the last third (PPL 4.82 vs. 5.46). Coverage helps. But B recovers ~85% of A's improvement over base while adapting only one third as many layers (≈ 0.3M vs. ≈ 0.9M params) — a defensible efficiency trade when budget is the binding constraint.

Modules

A vs. C — all-linear crushes attention-only (PPL 3.84 vs. 4.82, ≈ 20% lower). The single largest gain in the study comes from adding adapters to the MLP projections, not from more layers. Module breadth matters more than layer depth — plausibly because the MLP sublayers carry much of the capacity for the surface-level lexical patterns a narrow generation task leans on.

7.4  Best configuration, and a trade-off

C (all-linear, all layers) is best at PPL 3.84 and richest in vocabulary (Distinct-1 0.210); it is exported as tsv3-smollm135-best. A subtlety: C wins on modelling while A scores highest on Flesch readability (57.7 vs. 52.8). For the pedagogical target, C's stronger modelling is the headline; A is a lightweight runner-up when compute is scarce.

7.5  Qualitative check

Driving the exported models on an unseen prompt (a brave little turtle · a quiet pond · a sudden storm · the animals work together · teamwork overcomes fear) shows the difference concretely. The base model goes off-task, emitting essay-writing meta-commentary. The best (C) model writes a real fable:

"In the quiet pond, where water lilies swayed gently in the breeze and fish swam happily by, a brave little turtle lived among his friends… One day, dark clouds gathered over the pond as strong winds howled and loud thunderclaps rumbled… The clever rabbit, strong and swift, had been watching from a nearby rock. He suggested that they work together to save their friends… The two groups of creatures huddled closer and began working together…"

Minor artifacts (an occasional "(Figure 1)", slight character drift) are expected from a Q8-quantised 135M model and the prompt-format nuance in §09, but the output is unmistakably a coherent, on-prompt fable.

08Deployment: GGUF → Ollama → tinystory-vn

The academic result is delivered as a runnable model. For base and best (C): (1) merge the C adapter into the base (merge_and_unload); (2) convert to GGUF Q8_0 via llama.cpp (≈ 138 MB each); (3) write an Ollama Modelfile whose TEMPLATE reproduces the training format and stops on <|endoftext|>; (4) ollama create both models; (5) append two entries to tinystory-vn's config/models.json. Both models were created and verified behaviourally distinct (base off-task; best writes fables). Their Compare mode can then put our 135M fine-tune head-to-head against the 4B model. (ADR-0004.)

09Limitations & threats to validity

  • Absolute ceiling. 135M caps quality; the study is about relative placement efficiency, not beating a large model.
  • Single run, no intervals. One seed/schedule per arm; point estimates without confidence intervals (though the PPL gaps are comfortably separated).
  • Incomplete 2×2. The missing all-linear × last-third cell would test for an interaction between the two axes.
  • No judge panel yet. The four-axis LLM-as-judge is deferred; conclusions rest on perplexity and reference-free metrics.
  • Prompt-format mismatch downstream. Adapters trained on TF1's wording may score lower when driven by tinystory-vn's slightly different prompt. Accepted (ADR-0004).
  • Light data shuffle. A 10k-buffer streaming shuffle over the 50k subset — deterministic and identical across arms, but closer to "lightly shuffled head" than a uniform sample.

Two field notes for a Colab rerun

The torchao trap. Colab preinstalls torchao 0.10.0, which makes PEFT's LoRA injection raise on a version check. We don't use it — pip uninstall -y torchao.

Monitoring a flaky VM. The Colab kernel socket is unreliable for long calls. Run training as a background job and observe progress via the Hub (adapters appearing), not by tailing logs.

11Conclusion & future work

Under a strictly controlled budget, adapter placement measurably changes how well a small model learns to write fables. Covering all layers beats the last third, but the dominant lever is module breadth — attaching adapters to the MLP projections, not just attention, drives the best result (PPL 3.84, a 60% reduction from the untrained floor) while training only 3.5% of the model. A tiny, pretrained model plus well-placed low-rank adapters turns unreadable output into age-appropriate fables.

Future work: run the four-axis judge to corroborate the ranking; sweep the rank to separate placement from capacity; complete the 2×2 to test for interaction; and use the exported models for a quantitative small-vs-large comparison against the 4B sibling.
